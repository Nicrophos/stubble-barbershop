# STUBBLE — лабораторная №4 (Node.js + Express + PostgreSQL)

## Требования

- Node.js 20+ (рекомендуется 22 LTS).
- PostgreSQL, запущенный локально.
- Библиотеки из `package.json` (`npm install`).

## Первый запуск (Windows, VS Code / PowerShell)

1. Распакуй архив. Открой терминал **в папке `Stubble`**, где находится `package.json`.
2. Создай пустую базу `stubble_db` через DataGrip, pgAdmin или `CREATE DATABASE stubble_db;`.
3. Выполни SQL-код из файла `database.sql` в базе **stubble_db** (через DataGrip / pgAdmin).
4. Скопируй `.env.example` в `.env` и укажи пароль PostgreSQL в `DATABASE_URL`.
   Пример: `postgresql://postgres:мой_пароль@localhost:5432/stubble_db`
   Если в пароле есть `@`, `#`, `:` и другие спецсимволы, их нужно URL-кодировать.
5. Замени `SESSION_SECRET` на длинную случайную строку (не менее 32 символов).
   Можно сгенерировать командой `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
6. Выполни:

   ```powershell
   npm install
   npm start
   ```

7. Открой **http://localhost:3000**. Не открывай `index.html` двойным щелчком и не запускай через Live Server: API и авторизация будут работать только через Node.js.

> Для удобной разработки используй `npm run dev` вместо `npm start`.

## Что проверять в лабораторной

1. Нажми «ВОЙТИ» в шапке: появится модальное окно (не новая страница).
2. Нажми «Регистрация» и создай аккаунт (логин, пароль, ФИО, email, аватар).
3. После регистрации открывается `/profile` — закрытая страница.
4. Поменяй ФИО, почту, фото и пароль. Логин изменить нельзя.
5. Перезапусти браузер: сохранение авторизации обеспечивается Cookie и сессией в БД.
6. Нажми «ВЫЙТИ» и попробуй открыть `http://localhost:3000/profile` напрямую: без входа тебя перенаправит на главную с открытой формой входа.
7. В форме входа выбери «Забыли пароль?», укажи зарегистрированную почту. В **режиме лабораторной** появится ссылка для смены пароля (вместо отправки почтой; это разрешено методичкой).
8. Убедись, что все пять старых страниц, печатная версия и пять фильтров в прайсе сохранились.

## Структура

- `public/` — прежний STUBBLE: HTML, изображения, CSS, JavaScript, пять фильтров, печатная версия.
- `public/js/auth.js` — всплывающие окна регистрации/входа/восстановления.
- `private/profile.html` — защищённая страница личного кабинета.
- `public/js/account.js` — изменение данных, аватара и пароля.
- `public/js/reset-password.js` — смена пароля по одноразовой ссылке.
- `server.js` — Express: API, серверные проверки, сессии, загрузка аватара.
- `database.sql` — таблицы `users`, `password_resets`. Таблица `user_sessions` создаётся автоматически.
- `.env` — секреты подключения к БД, не добавлять в Git.
- `data/avatars` — аватары пользователей, вне публичных файлов.

## Безопасность

- Пароли в PostgreSQL сохраняются в виде bcrypt-хешей, а не открытым текстом.
- SQL-запросы параметризованные (`$1`, `$2`), ввод пользователей не соединяется со строкой SQL.
- На странице данные профиля вставляются через `textContent`, поэтому не интерпретируются как HTML.
- Используются серверная проверка доступа к `/profile`, CSRF-токен, ограничение попыток входа, безопасные сессионные Cookie (`HttpOnly`, `SameSite=Lax`), обновление ID сессии после входа.
- Загрузка аватаров ограничена 2 МБ и форматами JPEG/PNG/WEBP, с проверкой содержимого файла.
- Демо-ссылку восстановления пароля **нельзя** использовать на публичном сервере: в реальном проекте одноразовую ссылку нужно отправлять владельцу почты. `DEMO_RESET_LINK=true` работает только при `NODE_ENV=development`.
- Для публичного развёртывания нужно использовать HTTPS и отдельный хостинг для Node.js + PostgreSQL (GitHub Pages не выполняет серверный код).

## Для преподавателя

Это реализация функциональных пунктов ЛР4 на **Node.js + Express + PostgreSQL вместо PHP + Apache + MySQL**. Технологию нужно согласовать с преподавателем, поскольку методичка прямо называет PHP.
